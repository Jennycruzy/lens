Why Lens exists

Useful state is often a view call, not a transaction.

Attestcoin natively

Prove

  • This transaction was included.
  • This event was emitted.
  • This payment happened.
Lens adds

Verify

  • What did this view function return?
  • What were this vault's reserves?
  • What was voting power at block N?
  • Does this address hold this role?
  • What is this checkpointed exchange rate?

Lens turns read-only state into something Attestcoin can already prove. No protocol upgrade required. There are no storage proofs here and none are claimed: the contract answers, the answer is emitted, the emission is proven.

Limits

Built for finalized state, not instant state.

The attestation frontier trails the source head by minutes. A feed is only honest if its meaning survives that lag.

Good fit
  • 30-minute observations and TWAP inputs
  • liquid-staking exchange rates
  • reserves, backing and total supply
  • historical voting weight
  • roles, access lists and pause state
  • checkpointed values of any kind
Wrong fit
  • instantaneous AMM quotes
  • perp mark prices
  • block-sensitive liquidation engines
  • sub-minute trading signals

Lag is measured live above from the registry's attested frontier against each source chain's head. Gas figures are in docs/LATENCY.md, each with the transaction it came from.

Integrate

Three ways in.

Every read carries a freshness bound; there is no version without one.

Inherit LensConsumer. Resolve sourceKey from Creditcoin's ChainInfo for the environment you deploy to — chain keys are local to one environment, so never copy one from an example.


        

      

      

        
LensAggregatorV3 exposes an eligible Lens feed through the familiar AggregatorV3Interface, so contracts already written against it can consume slow-moving or time-averaged cross-chain state with minimal work. For that class of state only — not block-sensitive spot pricing or fast liquidations. A value whose original source is Chainlink keeps Chainlink's own trust assumptions; Lens removes the need for a trusted cross-chain reporter.

        

        

      

      

        
The SDK takes native chain ids and resolves Attestcoin chain keys for the current Creditcoin environment. It refuses explicitly and lets you re-check the bytes yourself.
