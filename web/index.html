Correctness

The value comes from the source-chain EVM. A forged probe was never in an attested block, so its proof fails.

Liveness

Anyone can submit a probe. Withholding only makes the feed stale — it can never make it wrong.

Failure

Stale, failed or truncated reads are refused instead of guessed.

Why Lens exists

Useful state is often a view call, not a transaction.

Attestcoin natively

Prove

  • This transaction was included.
  • This event was emitted.
  • This payment happened.
Lens adds

Verify

  • What did this view function return?
  • What were this vault's reserves?
  • What was voting power at block N?
  • Does this address hold this role?
  • What is this checkpointed exchange rate?

Lens turns read-only state into something Attestcoin can already prove. No protocol upgrade required. There are no storage proofs here and none are claimed: the contract answers, the answer is emitted, the emission is proven.

Limits

Built for finalized state, not instant state.

The attestation frontier trails the source head by minutes. A feed is only honest if its meaning survives that lag.

Good fit
  • 30-minute observations and TWAP inputs
  • liquid-staking exchange rates
  • reserves, backing and total supply
  • historical voting weight
  • roles, access lists and pause state
  • checkpointed values of any kind
Wrong fit
  • instantaneous AMM quotes
  • perp mark prices
  • block-sensitive liquidation engines
  • sub-minute trading signals

The attestation lag is measured live on the evidence page. Gas figures are in docs/LATENCY.md, each with the transaction it came from.
